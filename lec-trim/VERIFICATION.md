# Verification record — lec-trim v0.1.0, 2026-11-27

All checks ran on mock clips generated by `tools/make_mock_clips.py`
(ffmpeg `flite` speech synthesis, voice `slt`, H.264, keyframe interval
1 s, max B-frames 0, AAC 48 kHz), with the Whisper base English model
(`ggml-base.en.bin`, SHA-256
a03779c86df3323075f5e796cb2ce5029f00ec8869eee3fdfb897afe36c6d002)
and a locally built `whisper-cli` (whisper.cpp). Detection on real
student recordings is not verified by any check below.

## Results

- Unit tests: 10 passed (sorting, OBS timestamp keys, output versioning,
  phrase finding, whisper JSON parsing, part planning, path escaping).
- C1 Cue detection: all cues found in the three-clip set. Measured
  inpoints 3.43 s and 4.43 s against labelled phrase-end-plus-pad values
  of 3.64 s and 4.64 s (error about 0.2 s). Measured outpoints 10.95 s
  and 12.40 s against labelled values of 11.46 s and 12.32 s (errors
  0.51 s and 0.08 s). The 0.51 s error is at the stated 0.5 s gate;
  it comes from the recogniser's token time for "stop", not from the
  trimming, which the frame checks below show to be exact.
- C2 Cut accuracy: stitched output duration 23.63 s against a kept total
  of 23.01 s (+0.21 s per clip). An earlier build measured 31.42 s; the
  two causes were copied audio packets overrunning re-encoded parts and
  `-t` overrunning stream-copied parts. Both are fixed and the fixes are
  recorded in comments in `src/stitcher.rs`.
- C3 Middle is copied: the 180 frames of the first clip between its
  keyframes at 4 s and 10 s appear in the output as a bit-exact
  contiguous block (`framemd5`), starting at output frame 18, directly
  after the re-encoded head part. With B-frames in the source this
  check failed (the copied block started one keyframe interval late),
  which is why clips with B-frames are now re-encoded in full with a
  warning, and why the OBS guide sets max B-frames to 0.
- C4 Track selection: the clip with silence on track 1 and speech on
  track 2 selected stream 2.
- C5 Versioned output: covered by a unit test (v01, then v02, existing
  file untouched) and by the scanner excluding previous outputs.
- C6 Mismatched clip: a 320x240 MP4 clip in a 640x360 MKV set was
  re-encoded in full with a warning naming it; the output probed at
  640x360, duration 15.80 s against a kept total of 15.54 s.
- C7 Missed cue: a clip with no cue phrases was kept whole (8.14 s),
  both warnings named the file, and the stitch completed (8.22 s).

## Findings recorded during verification

- Whisper base heard the `flite` voice `kal` saying "start recording"
  as "stop recording" consistently in context, while voices `slt`,
  `awb` and `rms` were heard correctly. "Start" and "stop" are
  confusable for the recogniser; the mock generator uses `slt`, and the
  README tells students to say the full phrases exactly.
- Runtime on this machine (1.5 shared CPU cores) was about 2 minutes of
  recognition per short clip. That figure is a property of this
  throttled virtual machine, not an estimate for a student computer.

## Windows build

`lec-trim.exe` was cross-compiled for `x86_64-pc-windows-gnu` with
MinGW-w64 (PE32+ x86-64 console executable, verified with `file`). It
has not been run on Windows. The bundled `whisper-cli.exe` is the
whisper.cpp v1.7.6 release binary and `ffmpeg.exe`/`ffprobe.exe` are
the Gyan 9.1 essentials builds; neither has been run here.
