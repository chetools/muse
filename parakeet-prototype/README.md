# Parakeet transcription page

A static page that runs NVIDIA Parakeet TDT 0.6B v2 (English, int8)
entirely in the browser on WebAssembly. It is a general transcription
page for spoken engineering English: audio enters as an uploaded file
or a microphone recording, and the transcript is corrected with a
chemical-engineering glossary map.

## Layout

- `index.html` — the page. Its Content-Security-Policy limits network
  connections to this site and Hugging Face (`huggingface.co` and its
  download subdomains).
- `app.js` — page logic. It imports ONNX Runtime Web first and points
  its WASM binary paths at `vendor/ort/` on this site, before
  parakeet.js is imported, so the library's default CDN address for
  those binaries is never used.
- `segments.js` — timestamp formatting and segment assembly (pure
  functions, unit-tested).
- `autosave.js` — transcript autosave helpers (pure functions,
  unit-tested).
- `corrections.js` — the glossary correction map, generated, not
  hand-written (see below).
- `vendor/ort/` — onnxruntime-web 1.24.1, WASM build only
  (`ort.wasm.min.mjs`, `ort-wasm-simd-threaded.mjs`,
  `ort-wasm-simd-threaded.wasm`).
- `vendor/parakeet/src/` — parakeet.js 1.4.4 source (MIT, LICENSE kept
  alongside).

The model files are not in this repository. Pressing “Load model”
downloads them from the Hugging Face repository
`ysdede/parakeet-tdt-0.6b-v2-onnx` (about 670 MB, int8) and the browser
caches them.

## Corrections

`corrections.js` is generated by `gen_corrections.py` in the build
folder from `corrections.json` (203 pairs; 7 attested, 196 predicted),
the glossary correction map the Muse transcription skill uses.
Generation cleans each replacement term (full term when given,
trailing notes and parenthetical segments removed, category prefixes
and backtick fragments removed) and classes each kept pair:

- *certain* — a single clean term from a non-ordinary heard form;
  the transcript replaces the heard form outright.
- *slash* — uncertain: the heard form is an ordinary English word
  (checked against `ordinary_words.txt` in the build folder, which
  includes the skill's named traps) or the source term lists several
  candidate terms. The transcript shows the heard form followed by
  every cleaned candidate, slash-separated with no spaces, as in
  “viral/virial equation/virial coefficient”. One exception: for a
  pair with several candidates, if the word immediately after the
  heard form is the last word of exactly one candidate (or the word
  immediately before is the first word of exactly one), that
  candidate is used outright, the cue word is absorbed, and the
  application is logged as context-chosen with the cue word named
  (“viral coefficient” → “virial coefficient”).

A pair is excluded only when its cleaned term (or any cleaned
candidate) is empty, over 45 characters, or still carries a note
marker after cleaning. The audit of every pair's class, the excluded
pairs with reasons, and the cleaned pairs is `corrections-audit.json`
in the build folder; it is not published. Matching is
case-insensitive at word boundaries, longest heard form first, in a
single pass, so inserted text is never rescanned. The page lists
every correction it applies to a transcript and marks the uncertain
ones, because most pairs are predicted and a predicted pair can
over-correct an ordinary word.

## Timestamps

An “Include timestamps” option, off by default, prefixes each
transcript segment with its start time as [MM:SS] ([H:MM:SS] past one
hour). Segment times come from the transcription itself: in recording
mode, samples already transcribed divided by the capture sample rate;
in file mode, the start of each chunk returned by
`transcribeLongAudio` with timestamps enabled and the window's
`timeOffset` passed in (the vendored `long_audio.js` builds those
chunks from the model's word times).

## Autosave

While a transcript exists, the page saves it in the browser
(localStorage, key `parakeet.autosave.v3`) after every transcribed
segment and every 15 s; the in-browser save is written again when
the page closes, and a last file write is attempted then (a closing
browser may not let it finish, so the in-browser copy is the
guaranteed one at close). File transcription runs in windows of
25 s of audio, each window's segments autosaved as they land, so a
crash mid-file loses at most the window in progress. On desktop
Chrome, “Choose autosave file” also writes the same text to a chosen
file on disk on the same schedule, through the File System Access
API; file writes are serialised so two saves never open the same
handle at once. On load, a saved transcript is offered through a
Restore button; it is never restored silently. A Download button is
available whenever a transcript exists. A failed save is reported
in the autosave status line and never interrupts transcription.

## Telemetry

The telemetry observed on 2026-11-05 (`mobile.events.data.microsoft.com`,
OneCollector) came from the native desktop build of ONNX Runtime
1.31.1 used through Python. This page uses only the WebAssembly
build, which Microsoft's ONNX Runtime 1.29 release notes describe as
telemetry-free.

Audit performed on the exact vendored files before publication
(2026-11-05): string searches over every vendored text file and the
WASM binary for `mobile.events`, `events.data.microsoft`,
`microsoft.com`, `OneCollector`, `telemetry`, `sendBeacon`,
`google-analytics`, `googletagmanager`, `plausible`, `mixpanel`
returned zero matches. The only URLs in the vendored browser code
are `huggingface.co` (model download) and the jsDelivr fallback in
parakeet.js's backend module, which cannot trigger because `app.js`
sets the WASM binary paths before parakeet.js loads. Headless-browser
runs recorded every request: on page load, requests went to this
site only; after pressing “Load model”, to this site and
`huggingface.co` only.

## Verification state

Verified locally: node unit tests for the corrections map, timestamp
formatting, segment assembly and the autosave helpers; headless
Chromium loads with zero external requests and zero console errors,
no horizontal overflow at 1280 px or 390 px; the model-load failure
path (no public internet in the sandbox) shows a plain-language
error and re-enables the button.

Not verified from the sandbox: the real 670 MB model download,
inference speed and transcript accuracy, and real File System Access
file writes in desktop Chrome. Those are the user's laptop test; the
page's network log panel lists every fetched file so the test can be
checked while it runs.
