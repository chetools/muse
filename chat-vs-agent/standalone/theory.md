The four worked examples of the App panel are instances of a general distinction: how a number is produced determines what can go wrong with it and what evidence accompanies it. This panel defines the two production modes, derives the two error mechanisms that account for all four failures (aggregation over all terms, and cancellation in a difference of near-equal quantities), and states the consequence for engineering practice.

## The two modes of calculation

A language model of the transformer architecture {{cite:vaswani-2017}} produces text as a sequence of tokens, where a token is a unit of text, approximately a word fragment. At each step the model assigns probabilities to the possible next tokens given the preceding text and emits one token. The emitted text, including any digits, is the entire state of the computation: there is no separate arithmetic unit, no register holding an intermediate sum, and no record apart from the text itself.

In chat mode, the reply is produced in this way from beginning to end. A calculation requested in chat mode is therefore performed, if it is performed at all, as text generation: each partial result is written as characters, and subsequent steps operate on the characters written. The model may write out intermediate working, and the working may be long and largely accurate, but no step of it is executed by anything other than the text-generation process itself.

In agent mode, the model's text includes a program, and the program is executed by a computer before the answer is reported. The interleaving of model reasoning with actions in an external environment, of which program execution is the case of interest here, is the agent pattern described by Yao et al. {{cite:yao-2023}}. The numbers in the reported answer are then outputs of the execution: they were held in machine registers, accumulated in floating-point arithmetic, and can be accompanied by quantities the execution produced along the way, such as residuals. This page operates in agent mode: every computed value displayed was produced by the Python program listed in the Code panel, executed in the reader's browser.

The two modes are properties of a reply, not of a product, and current products cross the boundary in both directions. In the unified Claude product, a conversation begins as chat and continues into code execution in a managed cloud environment within the same conversation when a task requires it {{cite:anthropic-2026}}. ChatGPT likewise includes Python execution, under the name data analysis, within ordinary conversations, with usage limits set by plan {{cite:openai-2026}}. In both products the invocation is at the model's discretion: no interface setting guarantees execution for a given question, and a question the model treats as short arithmetic can still be answered as generated text. The chat mode of the screening is therefore a controlled condition rather than a product name: tool use was withheld, and the tool-call count of every chat reply was verified as zero. The same condition is obtained through an application programming interface (API) request that offers the model no tools. For any single answer, the mode is established by evidence in the reply: executed code with its output, or a file produced by execution. A numerical answer carrying no such evidence is an unaided answer, whatever the product that produced it.

## Number production in chat mode

Three properties of text generation bear directly on numerical work.

First, a sum over many terms must be accumulated in the text. To evaluate a sum of $N$ terms, where $N$ denotes the number of terms, the generating process must emit each partial sum as characters and carry it into the next step exactly. Nothing enforces the carry: a partial sum that is emitted incorrectly is indistinguishable, to the process itself, from a correct one, and every later step builds on the emitted characters.

Second, no residual is evaluated. Iterative and fitting calculations in executed form terminate on a computed test: a residual, a gradient norm, or a change between iterates falls below a stated tolerance. In text generation there is no quantity against which a termination test could be applied, because no equation is evaluated; the working ends when the text reaches a plausible stopping point.

Third, a stated uncertainty in chat mode is text of the same kind as any other. A standard error, a confidence interval, or a root-mean-square error printed in a chat reply has been generated as a plausible magnitude. It is not connected to any accumulation over the data, because no accumulation has taken place. Sections on aggregation and cancellation below show that the four recorded failures are exactly the quantities for which these three properties are decisive.

## Number production in agent mode

An executed program carries full floating-point precision through every step and evaluates residuals as a matter of course. A nonlinear least-squares fit by the Levenberg–Marquardt method {{cite:marquardt-1963}} terminates on the gradient of the sum of squared residuals; the covariance matrix of the parameters is computed from the same Jacobian matrix the solver accumulated {{cite:bates-watts-1988}}; a network solution can be substituted back into the loop equations and its residuals printed. The verification quantities in the App panel (the residual sum of squares, the loop residuals of the network, the difference of the totals at full precision) exist because the execution produced them. A reader can re-run the program, change an input, and observe the effect; the calculation is an object that can be audited, not a narrative that must be believed.

Executed arithmetic is not exact arithmetic, and its error behaviour is a studied subject {{cite:higham-2002}}. The relevant point for the comparison is quantitative: floating-point accumulation over 41 terms loses nothing at the precision of the data in the worked examples (the residual sum of squares is reproduced to five significant figures by an independent implementation), whereas the chat-mode errors in the same quantities were 39 percent and factors of 2.9 and 9.2.

## Aggregation over all terms

Let $C_i$ denote the measured concentration of reactant A, in mol/L, at point $i$ of a kinetic experiment, and let $\hat{C}_i$ denote the concentration predicted by a fitted model at the same point. The residual sum of squares is

$$\mathrm{SSE} = \sum_{i=1}^{N} \left( C_i - \hat{C}_i \right)^2$$

where $N$ denotes the number of points. The root-mean-square error is $\mathrm{RMSE} = \sqrt{\mathrm{SSE} / N}$, in mol/L. Both quantities are defined by the complete sum: no subset of the residuals determines them, and no estimate of a typical residual reproduces them, because the squares weight the largest residuals most heavily.

The parameters of the kinetic model are the rate constant $k$, in $(\mathrm{mol/L})^{1-n}\,\mathrm{min}^{-1}$, and the reaction order $n$, dimensionless, in the rate law $-\mathrm{d}C_A/\mathrm{d}t = k C_A^{\,n}$, where $C_A$ denotes the concentration of A in mol/L and $t$ denotes time in min. Writing the parameter vector as $\boldsymbol{\beta} = (k, n)$ and the Jacobian matrix as $\mathbf{J}$, with entries $J_{ij} = \partial \hat{C}_i / \partial \beta_j$, the covariance matrix of the fitted parameters is approximated by

$$\mathrm{Cov}(\hat{\boldsymbol{\beta}}) \approx s^2 \left( \mathbf{J}^{\mathsf{T}} \mathbf{J} \right)^{-1}, \qquad s^2 = \frac{\mathrm{SSE}}{N - p}$$

where $p$ denotes the number of fitted parameters ($p = 2$ here) and $s^2$ denotes the residual variance, in $(\mathrm{mol/L})^2$. The standard error of parameter $j$ is $\mathrm{SE}(\hat{\beta}_j) = \sqrt{ \left[ \mathrm{Cov}(\hat{\boldsymbol{\beta}}) \right]_{jj} }$. Every entry of $\mathbf{J}^{\mathsf{T}} \mathbf{J}$ is a sum over all $N$ points, and the matrix inverse couples the parameters: the standard errors depend on the geometry of the whole data set (the spread of the times, the curvature of the model, and the correlation between the parameters, 0.51 for $k$ and $n$ in Example 1), not on the scatter of the residuals alone {{cite:bates-watts-1988}}.

The chat-mode failures of Examples 1 and 2 sit precisely here. In Example 1 (41 points), the point estimates from chat mode were acceptable, and the root-mean-square error was high by 11 percent; the standard errors, which require the full accumulation and inversion, were high by factors of 2.9 (for $n$) and 9.2 (for $k$). In Example 2 (25 points), the root-mean-square error was high by 39 percent: the reply substituted the typical magnitude of the residuals for the accumulated sum of their squares. In both cases the failed quantity is the one whose definition is the accumulation. Under agent mode the accumulation is the computation itself, and the covariance matrix is a by-product of the fit; the failure has no opportunity to occur.

## Cancellation in differences of near-equal quantities

Let $a$ and $b$ denote two quantities of similar magnitude, and let $d = a - b$ denote their difference, with $|d| \ll |a|$. Suppose each of $a$ and $b$ carries an absolute error: the available values are $\tilde{a} = a + \delta_a$ and $\tilde{b} = b + \delta_b$, where $\delta_a$ and $\delta_b$ denote the absolute errors. The computed difference then carries the absolute error $\delta_a - \delta_b$, bounded by $|\delta_a| + |\delta_b|$, and its relative error is bounded by

$$\frac{|\delta_d|}{|d|} \le \frac{|\delta_a| + |\delta_b|}{|d|}$$

The denominator is the small difference, not the large terms: the relative error of the difference is amplified, relative to the relative errors of the terms, by a factor of order $|a| / |d|$ {{cite:higham-2002}}. Rounding is a special case: values rounded to a unit $u$ carry $|\delta| \le u / 2$ each, so a difference of rounded values carries a relative error of up to $u / |d|$.

Example 3 is this mechanism at full scale. The two total annualised costs are $a = 473{,}366.27$ dollars/yr ($D = 0.30$ m, where $D$ denotes the inside diameter in m) and $b = 473{,}205.19$ dollars/yr ($D = 0.28$ m); the requested saving is $d = 161.08$ dollars/yr, and the amplification factor $|a| / |d|$ is approximately 2,940. The chat-mode reply computed every component of both totals to within 0.1 percent — pressure drop from the Colebrook equation {{cite:colebrook-1939}}, pumping power, electricity cost, capital cost — and then reported the saving as approximately 140 dollars/yr, in error by 13 percent. At the reply's own rounding unit of $u = 100$ dollars/yr, the bound above admits a relative error of up to 62 percent in the difference; the executed totals rounded at the same unit difference to 200 dollars/yr, an error of 24 percent, as the App panel demonstrates. Precision carried through every component was destroyed at the final subtraction, the only step at which the answer was sensitive to it. Execution carries full precision to the subtraction, and the error does not occur.

## Remainders at a balance point

A flow fixed by a node balance is a difference by construction. In the network of Example 4, let $Q_{CE}$ denote the flow in pipe CE in m$^3$/s, $Q_{EF}$ the flow in pipe EF in m$^3$/s, and $q_E$ the demand at node E in m$^3$/s. Node E has no other connections, so continuity gives $Q_{EF} = Q_{CE} - q_E$. With $Q_{CE} = 0.04437$ m$^3$/s and $q_E = 0.050$ m$^3$/s, $Q_{EF} = -0.00563$ m$^3$/s. The chat-mode solution, obtained by the Hardy Cross iteration {{cite:cross-1936}}, was accurate in absolute terms throughout: six of seven flows within 1.5 percent, both requested heads within 0.2 percent. Its largest absolute flow error was 0.00063 m$^3$/s, and that error fell on the remainder: 0.00063 is 11 percent of $|Q_{EF}|$. A remainder inherits the absolute error of the quantities it differences, exactly as in the cost comparison, because the balance equations of the network hold in absolute terms while the requested accuracy is relative. The executed solution reports loop residuals below $5 \times 10^{-4}$ m, a check that has no counterpart in a generated reply.

## Distribution of the observed failures

The screening behind the worked examples covered 26 problems, of which 22 were solved correctly in full in chat mode, including a 56-stage distillation stepping, a nested flash iteration, and a 200-record aggregation that was exact in every requested statistic. The failures were not distributed over the calculations at random; each of the four is an accumulation over all terms, a difference of near-equal quantities, a remainder of near-cancelling quantities, or a stated uncertainty, which is an accumulation by definition. Iteration, in which each step consumes the output of the previous step and the structure of the equations constrains the trajectory, was sustained accurately even at large step counts. The discriminating question for a given quantity is therefore mechanical: is the quantity an aggregate, a small difference, or an uncertainty statement? If it is, chat mode supplies no reliable route to it, because the route is the accumulation or the exact subtraction, and neither is performed.

## Conditions under which chat mode is preferred

The conclusion for numerical work does not extend to all uses. Chat mode is the correct choice in six conditions, each characterised by the absence of a numerical result that will be relied on.

First, when the deliverable is prose: explanation, drafting, summarisation, translation, and orientation in an unfamiliar topic. The output is read and judged as text; execution contributes nothing, and the agent loop adds latency and approval steps without benefit.

Second, when the problem is not yet well-posed. Agent mode presupposes a specification: the quantity to be computed, the governing assumptions, and the property method. Converging on that specification is conversational work, and it must precede execution, because an agent supplied with a misposed specification returns a converged result for the wrong problem, with residuals that certify the execution and not the posing. The specification step is agent mode's own error class, and chat mode is where it is eliminated.

Third, when the reasoning itself is the object: instruction, assessment under examination conditions, and the evaluation of models. In each case the performance of interest is the unaided one, and tool use defeats the purpose of the exercise.

Fourth, when an unaided answer serves as an independent check on an executed result. An estimate by a diverse route — a limiting case, an order-of-magnitude bound, a short hand iteration — shares neither the code nor its specification, so an error in the specification does not replicate in the check. Such a check can falsify an executed result at the level of gross error; it cannot certify digits, and it is not a substitute for execution where digits are required.

Fifth, under access and governance constraints: data that may not enter a code-execution environment under the applicable terms, deployments without tool infrastructure, and settings in which least-privilege practice argues against granting file and execution access to answer a question that requires neither.

Sixth, when latency governs: a definitional or factual answer in a live exchange, including classroom use. An agentic run takes minutes, may require approvals, and can fail partway through; a chat reply arrives in seconds.

The boundary between the modes is the reliance placed on the output. In each condition above, no number will be sized against, designed to, or graded on. The moment a number acquires that status, the verification asymmetry derived in the preceding sections applies, and agent mode is required.

## Consequence for engineering practice

An engineering number is used inside a decision: a diameter is selected, a design margin is set, a result is graded. The number must therefore be checkable by the engineer who relies on it. A chat-mode number can be checked only by repeating its calculation, because the reply contains no residual, no covariance matrix, and no intermediate state that a shorter audit could verify; and repeating the calculation is precisely the work the chat was meant to save. The saving offered by chat mode is consequently illusory for any number that matters: the choice is between trusting the number unchecked and doing the calculation anyway. An agent-mode number arrives with its checks produced by the same execution (residuals, covariance matrix, loop balances), and auditing those checks is cheaper than the calculation. For numerical work there is accordingly no engineering reason to use chat mode in place of agent mode. The conditions under which chat mode is nevertheless the correct choice are stated in the preceding section; none of them involves a numerical result that will be relied on. The conclusion is restricted to what the evidence covers: one frontier model, one attempt per problem, undergraduate-scale well-posed problems, and the four failures analysed here; it identifies where chat-mode calculation fails and why, and the mechanism, not the sample, carries the recommendation.
